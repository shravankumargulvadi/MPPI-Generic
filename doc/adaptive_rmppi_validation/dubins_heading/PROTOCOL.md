5. The new plant feedback branch solves from the current state and applies `u_recovery[0] + K_recovery[0]*(x - x_recovery[0])`. Since x_recovery[0] = x, its gain term is zero at the applied step. Probe whether the existing baseline DDP solve already has the same initial state, gains and first control. If confirmed, any improvement needs to be attributed to executing a recovery/feedforward action rather than automatically to refreshed rollout gains. Also probe the documented one-solve-per-cycle claim using repeated getter calls.

The primary run and ablations use identical plant, cost, horizon, noise, constraints and seeds. All experiment settings are fixed before observing the default run. Do not infer that previous cart-pole outcomes apply unchanged to this newly changed controller or synchronization implementation.

The mechanism probe confirmed identical baseline/recovery gains and first DDP action for a 2.5 rad heading deviation, with the baseline trajectory starting exactly at the actual state. It also recorded two recovery solves for two getter calls in one cycle. The registered attribution check is therefore extended with an existing-DDP-action reuse baseline: stock executes the already computed DDP action outside the same radius, versus adaptive plant-only execution with rollout budget zero. This avoids an extra solve while using the same local DDP problem. All five cases use 30 paired seeds 1000-1029 and the unchanged four kick magnitudes. The primary `submitted` case runs an exact copy of the source from the fetched commit; the remaining cases use the instrumented harness with default-preserving optional flags.
